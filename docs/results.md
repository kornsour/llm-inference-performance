# Benchmark results

> Generated by `benchmarks/run_all.py` on **cpu** (cpu), torch 2.13.0, Python 3.14.7, 6 threads.

**Model:** 10.74M params · 6L/6H/384d · block 512 · vocab 256. **Workload:** prompt 64 → 128 new tokens, 5 repeats.


## 1. KV-cache (greedy decode, identical outputs)

| variant | tokens/sec | p50 latency (ms) | p95 latency (ms) | TTFT p50 (ms) | peak mem (MB) |
| --- | --- | --- | --- | --- | --- |
| no cache (O(T²)) | 178.68 | 710.335 | 740.608 | 2.74 | 9.0 |
| KV-cache (O(T)) | 908.14 | 136.649 | 151.464 | 2.916 | 7.04 |

**KV-cache speedup: 5.08× tokens/sec.**

The cache is memory *spent*, not saved: it holds **3.52 MB** of K/V resident at the end of this run (64 + 128 tokens), and grows linearly with sequence length and batch size. Peak memory is the high-water mark of tensor bytes allocated inside each decode, above the resident model — see [`docs/methodology.md`](methodology.md).
